## Runtime cloud configuration

Use either the app's **More → Cloud backup** screen on each trusted device, or
the build-time environment variables below. The in-app route is preferred for
public web builds because it avoids embedding the private sync code in the
JavaScript bundle.

| Name | Required? | Purpose and source |
|---|---:|---|
| `VITE_SUPABASE_URL` | For preconfigured cloud sync | Supabase project URL from **Project Settings → API**. |
| `VITE_SUPABASE_ANON_KEY` | For preconfigured cloud sync | Supabase publishable/legacy anon public key from **Project Settings → API**. Do not substitute the service-role key. |
| `VITE_SUPABASE_SYNC_CODE` | For preconfigured cloud sync | Owner-generated private business code, at least 20 characters, identical on trusted devices. It is the RLS tenant boundary and must be stored like a password. |
| `NEXT_PUBLIC_SUPABASE_URL` | Alternative only | Node/Vinext fallback alias for `VITE_SUPABASE_URL`. Do not set both to different values. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Alternative only | Node/Vinext fallback alias for `VITE_SUPABASE_ANON_KEY`. |
| `NEXT_PUBLIC_SUPABASE_SYNC_CODE` | Alternative only | Node/Vinext fallback alias for `VITE_SUPABASE_SYNC_CODE`. |

The app also stores cloud configuration locally under the browser key
`mantu-supabase-config-v1`. That value is deliberately excluded from the local
data-export script and this archive.

## GitHub Actions secrets

These are needed only when manually running the real native offline-sync test.
Use a dedicated empty test Supabase project, never the production shop project.

| GitHub Actions secret | Purpose and source |
|---|---|
| `MIDORI_E2E_SUPABASE_URL` | HTTPS URL of the dedicated test project. |
| `MIDORI_E2E_SUPABASE_ANON_KEY` | Publishable/anon key of the dedicated test project. |
| `MIDORI_E2E_SYNC_CODE` | Test-only random code of at least 20 characters. |

`MIDORI_E2E_RUN_KEY` is generated by the workflow and is not a stored secret.
`MIDORI_TAURI_BINARY` is a generated local path and is not a secret.

## Backup and restore tool variables

Set these only in the terminal session that performs the export or restore.
Do not save them in this repository.

| Name | Purpose and source |
|---|---|
| `SUPABASE_DB_URL` | Postgres connection string from **Supabase → Project Settings → Database → Connection string**. Prefer the session pooler if direct IPv6 connectivity is unavailable. Contains a database password. |
| `MIDORI_BUSINESS_ID` | Existing private business sync code used to filter the export to one business. |
| `NEW_MIDORI_BUSINESS_ID` | Private sync code to bind restored rows to in the new project. It may be the old code or a newly generated code of at least 20 characters. |

## Account credentials that are not project environment variables

- GitHub authentication: SSH key, passkey, GitHub CLI login, or a fine-grained
  personal access token with access to the destination repository.
- Supabase CLI authentication: interactive `supabase login` token and the
  database password chosen when creating the project.
- Signing credentials are **not configured in this snapshot**. Apple Developer,
  Windows code-signing, Android upload-key, and store credentials are required
  only when signing/notarizing/publishing later.

## Explicitly not required in this snapshot

No Razorpay, Twilio, MSG91, Firebase, Sentry, PostHog, Stripe, email provider,
SMS provider, OAuth provider, AWS, or Google Maps credential was found in the
tracked source. A conditional `google-services.json` hook exists in the Android
Gradle file, but there is no Firebase SDK or configuration file and it is not an
active integration.
